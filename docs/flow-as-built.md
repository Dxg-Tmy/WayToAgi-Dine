# 麦点点 · 实现版流程说明（as-built，对应 web/app.js）

> 本文件描述**最终实现的真实行为**，与 `web/app.js` 一一对应。
> 早期的 `flow-design.md`（v2）与 `flow-plan-v3.md`（v3）是设计稿，已被本文件取代，仅作过程留档。

## 1. 输入规范（3 键，无回退）

| 输入 | 行为 |
|---|---|
| **▲ 上一个** | 当前列表高亮上移一项，到顶循环到底 |
| **▼ 下一个** | 当前列表高亮下移一项，到底循环到顶 |
| **确认（短按）** | 选中当前高亮项，并前进一步 |
| **确认（长按 ≥0.8s）** | 已有订单时**直接进入结算界面**（支付页可再核对订单明细）；无订单时提示「还没选东西」 |
| 加购弹窗中的输入 | 按 ▲/▼ = 在「来饮料 / 来小食 / 直接结算」之间切换；按「确认」= 选中 |

输入来源三路完全等价：屏幕三个大按钮 / 键盘（`↑` `↓` `Enter`，`Shift+Enter` 等效长按）/ RP2350 点餐盒（HID `1=下一个 2=上一个 3=确认`（长按=4））。
右上角「设置」可勾选「使用实体点餐盒」，勾上后隐藏屏幕按钮（`body.physical`），流程不变。

## 2. 页面结构（最多 3 个选择页）

```
ENTRY ──套餐──▶ COMBO_LIST ──选定──▶ COMBO_CONFIG ──配完──▶ CHECKOUT ──▶ PAY ──▶ DONE
  │                                    （第 3 步：逐轮配置）
  └──单点──▶ CATEGORY_LIST ──选定──▶ ITEM_LIST ──选定──▶ [加购弹窗] ──▶ CHECKOUT ──▶ PAY ──▶ DONE
              （第 2 步）              （第 3 步）
```

| 页 | 内容 | 选项数 |
|---|---|---|
| **ENTRY** | 想怎么点？ | 2：套餐 / 单点 |
| **COMBO_LIST** | 选一个套餐（`Catalog.topCombos(5)`） | 5 |
| **CATEGORY_LIST** | 单点分类（动态生成，缺货不显示） | 2–5：主食·辣 / 主食·不辣 / 小食 / 饮料·冷 / 饮料·热 |
| **ITEM_LIST** | 该分类的 Top3（`Catalog.topN(items, 3, BEST)`） | 3 |
| **COMBO_CONFIG** | 按 `query-meal-detail` 的 `rounds` 逐轮配置 | 每轮 ≤3 |
| **CHECKOUT** | 订单清单 + 合计 | 订单行 |
| **PAY / DONE** | 支付（二维码自适应）/ 完成 | — |

## 3. 选品目录如何从真实菜单派生（`Catalog.build()`）

1. 按 `code` 去重；
2. **排除周边**：`/周边|帽/` 命中名称，或 `tags` 含「汪苏泷限量周边」（排除「旋旋水手帽 ¥48.8」）；
3. **判定套餐**：名称含 `套餐|三件套|四件套|随心配|随心选|百宝袋`，或 `tags` 含 `套餐/小食拼盘/经典精选/大口吃肉好快乐/超值百种组合随心配/麦金卡`；
4. **主食单品** = 非套餐且分类为「巨无霸/牛鱼肉堡」「炸鸡」「鸡肉汉堡/卷」；
   - 辣 = 名称命中 `/辣|椒盐|麻辣|香辣|酸辣/`（麦辣鸡翅、那么大鸡排）
   - 不辣 = 其余（双层吉士汉堡、麦香鱼、双层深海鳕鱼堡、麦乐鸡、薄皮焦香V翅…）
5. **小食** = 分类「小食甜品/其他」中的非套餐单品；
6. **饮料** = 分类「饮品」「麦咖啡」；冷/热先用 `tags`（冷饮/热饮），无 tag 按名称（雪冰=冷；咖啡/红茶/黑巧/牛奶=热）；
7. **Top3 排序** = 人工置顶名单 `BEST` / `BEST_COMBOS` 优先，其余按 `tags` 权重（爆款 3 > 人气 2 > 超值 1.5 > 麦金卡/学生 1）。

> MCP 不返回销量，「最常点」= 名单 + 标签权重，**不伪造销量**。改 `app.js` 顶部的 `BEST` / `BEST_COMBOS` 即可调整门面商品。

## 4. 套餐配置算法（`renderComboStep` / `comboOk`）

对选中套餐调用 `query-meal-detail`，拿到 `rounds` 后：

1. **固定格自动跳过**：某轮只有 1 个 `choice` → 直接记为答案并进入下一轮，不占用用户按键
   （例：「精选单人餐三件套」的主食轮只有「原味双层深海鳕鱼堡」）。
2. **辣度询问**：主食轮若同时存在辣与不辣选项 → 先问「辣还是不辣？」（2 选），再按结果给 3 个。
3. **冷热询问**：饮料轮若同时存在冷与热 → 先问「冷饮还是热饮？」（2 选），再按结果给 3 个
   （例：该套餐饮料轮有 26 个选项，冷热都有）。
4. **截断**：每轮最多展示 3 个，`isDefault=1` 排最前。
5. 全部轮次完成 → 标题「套餐已配好」，订单写入该套餐（含配置答案）；此后长按「确定」结算。

离线（快照）模式下拿不到 `rounds`，降级为「按默认搭配」并提示，不阻塞流程。

## 5. 单点加购弹窗（`renderUpsellModal` / `upsellOk`）

单点选中一个单品后弹「还要加点吗？」三选（▲▼切换、确定选中）：

| 选项 | 去向 |
|---|---|
| **来一个饮料吧** | 先问冷/热 → 该温度 Top3 → 选中后**追加**进订单 → 直接进 CHECKOUT |
| **来一个小食吧** | 小食 Top3 → 选中后**追加**进订单 → 直接进 CHECKOUT |
| **直接结算** | 不进加购，直接 CHECKOUT |

「追加」由 `App.adding` 标记控制：`adding=true` 时 `pickItem` 把商品 `push` 进订单而非替换。

## 6. 结算与支付

- `orderTotal()` = 订单行 `price`（分）求和；展示层 `fen2yuan()` 除 100。
- CHECKOUT 页按「确定」进入 PAY；PAY 页默认**模拟支付**（设置里可取消勾选），二维码为确定性演示图案，
  尺寸 `max-width:min(220px,60vw); aspect-ratio:1`，永不裁切。
- 真实下单链路（`calculate-price` → `create-order` → `cancel-order`）已在早期版本 live 验证通过（见 `workbuddy.md` §9），当前版本未默认开启。
- 按「确定」→ DONE（显示合计）→ 再按「确定」→ `newOrder()` 回到 ENTRY。
