# 麦点点 · 无障碍顺序点餐（MaiDianDian）

> 让看不清楚、识字困难的人，不靠眼睛也能自己点麦当劳。
> WaytoAGI 1024 切磋大会 · 用餐赛道参赛作品 / 同步参加麦当劳程序员创意开发大赛

## 这是什么

一个「顺序确认」式的无障碍点餐作品：用户不需要浏览复杂菜单、不需要看清屏幕、不需要输入文字，
只需要 **三个按键**（**▼ 下一个 / ▲ 上一个 / 确认**，长按确认直接结算）就能完成一次点单。
全程大字号、高对比、可选语音播报，菜单、价格、套餐组成全部来自**麦当劳 MCP 真实调用**。

核心设计目标：**最多 3 个页面就完成选择**。所以不做「59 项逐个翻」的长列表，而是：

1. 先问「**套餐 / 单点**」；
2. 选套餐 → 列出 5 个高频套餐 → 展开该套餐的真实可选组成（主食/小食/饮料逐项配）；
3. 选单点 → 按「**主食·辣 / 主食·不辣 / 小食 / 饮料·冷 / 饮料·热**」分流 → 每类只给 **3 个最常点的**；
4. 单点只选一个主食时，弹窗追问「**来一个饮料吧 / 来一个小食吧 / 直接结算**」；
5. **长按「确认」**随时直接进入结算界面（支付页可核对订单明细）；右上角「回到主菜单」可随时清空订单回首页。

**与现有方案的差异**：肯德基的无障碍靠「人换人」（聋哑员工 + 手写板），麦当劳 App 和自助机靠「让你看清了自己点」；
麦点点把点餐从「浏览选择」重构为「顺序确认」——不依赖视觉精度、不依赖文字输入，插上就用。

## 三种用法

| 模式 | 适用场景 | 数据来源 |
|---|---|---|
| **A. 本地完整模式**（推荐演示） | 笔记本 + RP2350 点餐盒，真实 MCP 调用 | Node 代理实时调 `https://mcp.mcd.cn` |
| **B. 云端静态版** | 评委/用户手机直接打开链接 | 开发时经 WorkBuddy `mcd-mcp` 连接器拉取的真实数据快照 |
| **C. 纯屏幕/键盘模式** | 没有硬件时 | 同 A/B，键盘（↑/↓/Enter）或页面三个大按钮驱动 |

三种模式共用同一套流程；右上角「设置」可切换「使用实体点餐盒 / 使用屏幕按钮」，二者流程完全一致。

## 快速开始

### 模式 A：本地完整模式（带硬件 + 真 MCP）

```bash
# 1. 配置 Token（open.mcd.cn/mcp 手机号申请；.env 不会进 Git）
cp proxy/.env.example proxy/.env
# 编辑 proxy/.env：填入 MCD_MCP_TOKEN，演示门店写 MCD_STORE_CODE=3450379

# 2. 启动（零依赖，Node 18+）
cd proxy && npm start        # 或 node server.mjs

# 3. 浏览器打开 http://localhost:8787 （localhost 是安全上下文，WebHID 可用）
#    插上点餐盒 → 设置里勾选「使用实体点餐盒」，之后全程用三个物理按键
```

按键说明：`▼` 下一个 / `▲` 上一个 / `确认` 选中并前进；**长按 `确认`（≥0.8 秒）直接进入结算界面**
（结算页可逐行核对订单明细）。键盘端用 `↓/↑/Enter`，`Shift+Enter` 等效长按。
随时可点顶栏「回到主菜单」清空订单；**无操作 60 秒自动清空并回到主界面**（可关闭或改为 30/120 秒）。

### 模式 B：云端静态版

直接打开部署链接（GitHub Pages：`https://<用户名>.github.io/<仓库>/web/`；CloudStudio 链接作为备用），
或本地起任意静态服务器托管 `web/` 目录。页面右上角会显示当前数据模式（实时菜单 / 本地缓存 / 离线菜单）；
快照数据由 `proxy/refresh-snapshot.mjs` 生成。

### 固件烧录（RP2350 点餐盒）

```bash
bash firmware/build-flash.sh        # 一键编译 + 烧录 + 自检
```

按键映射（固件 v2.0.0）：`0x01`=下一个(D0) / `0x02`=上一个(D1) / `0x03`=确认(D4 短按) / `0x04`=确认·长按(D4 按住 ≥0.8s，直接进结算)。
D0/D1/D4 均为 `INPUT_PULLUP`，按键另一脚直接接 GND，**无需外接上下拉电阻**；
硬件**已去掉 LED 与蜂鸣器**（按键提示音由网页用 Web Audio 现场合成，不占 IO）。
一键脚本完成编译 → 1200 波特触碰自动进 BOOTSEL → picotool 烧录 → 9 项自测，全流程零人工。

## 数据从哪里来（MCP 集成）

菜单、价格、套餐组成全部来自麦当劳 MCP，核心调用：

| 工具 | 用在哪 |
|---|---|
| `query-meals` | 拉门店真实菜单（13 分类 / 59 项，含 tags） |
| `query-meal-detail` | **展开套餐可选组成**：返回 `rounds`（主食/小食/饮料逐轮的 `choices`、`diffPrice`、`isDefault`） |
| `now-time-info` | 官方时间，判断当前餐段 |
| `query-nearby-stores` | 定位门店（city + keyword 必填） |
| `list-nutrition-foods` | 热量数据（预留：浏览时可播报约多少千卡） |
| `calculate-price` | 真实算价（返回**分**），同时作为「售罄探活」 |
| `create-order` / `cancel-order` | 下单 / 取消（演示默认 mock，可在设置里切真实） |

详见 [MCP_INTEGRATION.md](MCP_INTEGRATION.md)。MCP Token 只保存在服务端环境变量 / WorkBuddy 连接器中，
**从不进入前端代码、公开仓库或截图**。

### 数据现实与取舍（重要）

MCP 有两类信息**取不到**，作品用可解释的替代方案，不造假：

- **没有销量字段**：`query-meals` / `query-meal-detail` 都不返回销量或排名，只有 `tags`（爆款/人气/超值）。
  → 「最常点的 3 个」＝ `tags` 权重排序 + `app.js` 里的人工置顶名单（`BEST` / `BEST_COMBOS`），改名单即可调整。
- **没有辣度字段**：只能按菜名推断（麦辣/辣/椒盐＝辣，其余＝不辣），集中在 `isSpicy()` 一个函数里可改。
- 品类标签里有「冷饮/热饮」，所以饮料的冷热询问是**真数据**驱动。

## 目录结构

```
web/                 前端（静态部署目标目录）
  index.html app.css app.js     3 键向导状态机 + 语音 + WebHID + 双模式数据
  data/menu-snapshot.json       真实数据快照（refresh-snapshot.mjs 生成）
  data/menu.md                  本地 Markdown 缓存（人可读，含实物图链接）
  smoke-test.mjs                Node DOM 桩冒烟测试（43 项断言，离线全流程）
  smoke-combo.mjs               真实 query-meal-detail 套餐配置冒烟（13 项断言）
proxy/               本地 Node 代理（零依赖）
  server.mjs                  静态托管 + MCP 转发（Token 只在服务端）+ 15 分钟菜单缓存
  mcp-client.mjs              Streamable HTTP JSON-RPC 客户端 + 菜单归一化
  refresh-snapshot.mjs        拉真实菜单 → 快照 + menu.md
  mock-mcp-server.mjs         按官方协议写的模拟 MCP Server（无 Token 联调）
firmware/ hardware/   RP2350 点餐盒固件与硬件（由协作 agent 完成）
docs/                使用说明、流程设计稿、实现版说明
workbuddy.md         开发对话记录（WorkBuddy 制作证明）
```

## 演示建议（3 分钟路演）

1. **痛点**（30s）：麦当劳 App 要点亮屏幕、看清、识字——看不清楚的人怎么办？
2. **演示**（90s）：三个物理按键走完「套餐 → 配好组成 → 结算」；再演示单点一个主食，
   弹窗问「要不要来杯饮料」；全程语音播报。评委手机打开静态链接也能同样走一遍。
3. **证据**（40s）：设置面板里打开「MCP 调用记录」——刚才的菜单和套餐组成都是真的；
   真实用户试用截图/录屏。
4. **下一步**（20s）：铺到特殊教育学校、聋哑人社区、门店柜台；硬件 BOM 成本约 30 元。
